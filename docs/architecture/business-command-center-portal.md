# Business Command Center: Commercial Portal Architecture

Technical specification defining the architecture, execution model, component boundaries, and backend integration of the **Business Command Center** (`business_command_center/`).

---

## 1. System Topology & Technology Stack

The Business Command Center serves as the web management interface for inspecting evaluations, executing war room adjustments, and downloading generated deliverables:

- **Frontend Framework:** Next.js 16 (Turbopack) with React 19 Server Components and Server Actions.
- **Enterprise CRUD Engine:** Refine.dev v5 core (`@refinedev/core`, `@refinedev/nextjs-router`) for unified resource management.
- **Styling & Design System:** Tailwind CSS v4, Radix UI primitives, Lucide React icons, and Framer Motion animation primitives.
- **Validation & Form State:** React Hook Form coupled with Zod schema resolvers.
- **Cryptographic Authentication:** Local sovereign authentication using PBKDF2-SHA512 password derivation (`engine_config/users.json`), one-time password verification (`engine_config/otp_store.json`), and filesystem-isolated tenant contexts.
- **Daemon & Production Gateway:** Systemd managed unit (`assessment-portal.service`) listening on internal port `3001`, reverse-proxied by Caddy with automated TLS termination.

---

## 2. Core Functional Modules

### A. Multinational Archetype Selector
Inspects multi-tenant portfolios across pre-configured corporate entities:
- `Nordic Grid Power GmbH` (Energy / Critical Infrastructure - PIC)
- `Global Nippon Financial Group` (Banking / Global Finance)
- `Meridian BioHealth Inc.` (Pharmaceutical / Life Sciences)
- `Iberia Retail Logistics S.A.` (Supply Chain / Logistics)

### B. Actuarial Integration & Dynamic Synchronization
Directly consumes synthesized JSON payloads (`fair_actuarial_model.json`, `approved_annex_payload.json`) to project:
- Currency localization (`EUR €`, `JPY ¥`, `USD $`) across labor rates and financial risk exposures.
- Monte Carlo probability distributions for Loss Event Frequency (LEF) and Vulnerability (VULN).
- Vector radar chart visualization rendered inline via `/api/download?view=inline`.

### C. Deliverable Export Engine
Direct binary streaming of customer artifacts generated by the Python compilation engine:
- Technical Annex (`Anexo_<tower>_ASIS.docx`)
- Technical Blueprint (`Blueprint_<tower>.docx`)
- Commercial Proposal (`Account_Action_Plan.docx`)
- Vector Radar Graphic (`radar_chart.png`)

### D. Tactical War Room (ADR Mutator)
Interactive scenario simulation allowing operators to inject ad-hoc technical constraints (e.g., budget cuts, vendor restrictions). The service uses bounded AI synthesis with deterministic fallbacks to recalculate initiative roadmaps and delivery waves.

---

## 3. Server Actions & Backend Coupling

Integration between Next.js and the Python engine is mediated through Server Actions:

| Server Action | Implementation File | Underlying Engine Responsibility |
|---|---|---|
| `getAssessmentState` | `src/app/actions/assessment.ts` | Inspects workspace directory, validates payload JSON schemas, and returns status. |
| `downloadDeliverable` | `src/app/api/download/route.ts` | Streams OpenXML `.docx` binaries directly from `workspaces/<client_id>/`. |
| `mutateArchitecture` | `src/app/actions/war_room.ts` | Executes scenario recalculation against `engine_config/` ontologies. |
| `uploadEvidenceZip` | `src/app/actions/upload.ts` | Client-side unpack via `jszip` and secure ingest into `source_docs/<client_slug>/`. |

## 4. Verification Oracles & Diagnostic Suites

Portal reliability is validated by automated diagnostic scripts:
- `tests/diagnostics/diag_verify_full_ui_render.py`: Asserts binary HTTP download headers and payload byte streams.
- `tests/diagnostics/diag_e2e_browser_validation.py`: Headless Chromium DOM evaluation asserting zero console errors.
- `tests/diagnostics/diag_run_full_user_journey.py`: End-to-end simulated operator workflow traversing login, archetype selection, and deliverable inspection.
