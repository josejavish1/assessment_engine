### MASTER REMEDIATION PLAN

To guarantee 100% compliance with the Tier-1 Global Scalability Mandate and achieve zero audit findings without breaking existing functionality, we will execute the following 4-Phase Remediation Plan.

#### Phase 1: Codebase Hygiene & Linguistic Purification (Vector 2)
**Objective**: Eliminate all non-English comments and remove inline language branching from the AST compilers and linguistic guardrails.
1. **Comment Translation (`generate_asis_markdown_modules.py`)**:
   * Replace the Spanish comment at line 847 with clear Technical English: `# 5. Write consolidated executive summary file`.
2. **AST Builder Decoupling (`ast_appendices_builder.py`)**:
   * **Pattern**: *Declarative Locale Resolution*.
   * **Action**: Remove `elif meta_lang == "es" and raw_kname:`. Delegate the resolution of `raw_kname` vs. localized names entirely to the `i18n` translation resolver or uniform metadata attribute lookup, ensuring identical behavior across `en`, `es`, `pt`, `fr`, `de`, and `ja`.
3. **Linguistic Guardrail Abstraction (`linguistic_guardrail.py`)**:
   * **Pattern**: *Strategy / Capability Metadata Pattern*.
   * **Action**: Replace `if base_loc == "ja":` at line 174 with a declarative capability check against the locale profile (e.g., `if locale_profile.is_logographic:` or `if not locale_profile.uses_word_spaces:`). Define these linguistic properties in the declarative locale configuration rather than hardcoding ISO-639-1 codes in Python logic.
4. **i18n Resolver Constant Extraction (`i18n/resolver.py` & `ast_table_builders.py`)**:
   * **Action**: Replace inline ternary fallbacks (`if locale else "en"`) with a helper method `_normalize_locale(locale: str | None) -> str` backed by a single imported constant `FALLBACK_LOCALE` to satisfy static analysis and centralize default locale governance.

#### Phase 2: Actuarial Currency & Scale Invariance (Vector 3)
**Objective**: Eradicate all hardcoded `"EUR"` defaults and inline currency dictionaries from the actuarial domain layer.
1. **Externalize Currency & Parity Catalogs (`actuarial_scale_calibrator.py`)**:
   * **Pattern**: *Externalized Configuration / Repository Pattern*.
   * **Action**: Move the static exchange rate parity table (line 74) and symbol-to-ISO mapping dictionary (line 425) into a declarative JSON/YAML data file (e.g., `currency_catalog.json`) or the existing `LocaleFormattingContract`.
2. **Eliminate Default `"EUR"` Signatures (`actuarial_scale_calibrator.py` & `downtime_calibrator.py`)**:
   * **Pattern**: *Explicit Context Injection / Contract Fallback*.
   * **Action**: Remove `= "EUR"` and `or "EUR"` from all function signatures and bodies (lines 391, 393, 451, 453, 483, 546, 653, 674).
   * Change default parameter values to `currency: str | None = None`.
   * When `currency` is `None`, resolve the active currency dynamically via `LocaleFormattingContract.get_default_currency(locale)` or a centralized `ActuarialCurrencyConfig.BASE_NUMERAIRE` constant (representing the internal mathematical numeraire unit, decoupled from presentation currency).

#### Phase 3: Jurisdictional Registry Decoupling (Vector 4)
**Objective**: Resolve the `CORE_REGULATOR_HARDCODED` findings in `framework_urn.py` while preserving deterministic URN resolution across global jurisdictions.
1. **Externalize URN Alias Mappings (`framework_urn.py`)**:
   * **Pattern**: *Data-Driven Registry Pattern*.
   * **Action**: Move the hardcoded URN constants and alias dictionaries (including `US_HIPAA_2013` and `US_FEDRAMP_R5` at lines 81, 85, 195, 207) out of Python source code and into a declarative registry file (e.g., `catalogs/frameworks/urn_registry.json` or `.yaml`).

This guarantees that adding a new banking, aviation, or healthcare regulation from any country requires zero modifications to core Python domain code.
